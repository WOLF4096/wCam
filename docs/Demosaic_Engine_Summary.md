# wCam 去马赛克引擎：整体完整性深度分析报告

## 1. 引擎架构评估
wCam 的去马赛克引擎采用了 **C++/NDK + OpenMP** 的架构，整体框架设计合理且具备专业基础：
- **流水线完整性**：底层 Common 模块实现了从黑电平扣除、白平衡、镜头阴影校正 (LSC)、色彩矩阵转换 (CCM) 到色调映射 (Tonemap) 和 Gamma 校正的全套流程。
- **高性能设计**：关键循环通过 `#pragma omp parallel for` 实现了多核并行，这在处理高像素 RAW 数据时至关重要。
- **高兼容性**：支持 8-bit 和 16-bit 输出，适配了全部四种 Bayer 模式。

## 2. 具体算法完整性盘点
经过对源代码的深度审计，发现算法层存在明显的“名不副实”现象：

| 算法名称 | 实际运行逻辑 | 完整性状态 | 备注 |
| :--- | :--- | :--- | :--- |
| **Fast (Bilinear)** | Bilinear | **100% (完整)** | 基础算法，实现正确 |
| **AHD** | 简化边缘导向插值 | **40% (残缺)** | 缺少同质性分析和多向过滤 |
| **RCD** | 简化比率插值 | **70% (良好)** | 逻辑骨架完整，缺乏后续细化 |
| **AMaZE** | RCD | **0% (占位)** | 仅有空壳，重定向至 RCD |
| **DCB** | RCD | **0% (占位)** | 仅有空壳，重定向至 RCD |
| **LMMSE** | AHD | **0% (占位)** | 仅有空壳，重定向至 AHD |
| **VNG4** | AHD | **0% (占位)** | 仅有空壳，重定向至 AHD |
| **EAHD** | AHD | **0% (占位)** | 仅有空壳，重定向至 AHD |
| **HPHD** | AHD | **0% (占位)** | 仅有空壳，重定向至 AHD |
| **IGV** | Bilinear | **0% (缺失)** | 底层完全未处理，退化为双线性插值 |

## 3. 核心问题点
1. **算法重定向风险**：项目中 10 个去马赛克选项中，有 7 个其实是通过重定向到 AHD、RCD 或 Bilinear 实现的。用户在 UI 界面切换算法时，大部分情况下观察不到画质变化。
2. **IGV 完全失效**：IGV 选项在底层代码中完全被遗漏，直接退化到了最简单的 Bilinear 算法。
2. **逻辑简化过度**：即使是 AHD，也丢弃了其最核心的同质性判断逻辑，导致其在复杂纹理下的表现远未达到预期。
3. **LSC 性能瓶颈**：目前的 LSC 计算在 `get_raw` 内部进行，这意味着对于每一个插值计算出的像素，都要重新计算双线性插值的 Shading Map 增益，这会产生巨大的计算开销。

## 4. 后续开发建议
- **补齐 Amaze/DCB**：这两个算法是专业 RAW 处理器的核心，建议优先引入 LibRaw 等成熟库的逻辑。
- **预计算缓存**：将 LSC 的增益预先计算并应用到缓存的 RAW Buffer 中，避免在插值循环内重复计算。
- **引入算法标识**：在 UI 或日志中明确告知用户哪些算法处于 Beta 或占位状态，避免误导。

## 5. 总结
wCam 的去马赛克引擎拥有一个**专业级的骨架**，但填充的**内容（算法实现）目前还处于初级阶段**。它是一个优秀的开发原型，但在画质上还有极大的提升空间。
