# wCam 拍摄流程（Capture Pipeline）算法分析报告

## 1. 算法概览
拍摄流程负责从获取原始图像数据到最终文件落盘的全过程，涵盖了格式转换、元数据嵌入、水印处理及存储兼容性管理。

## 2. 核心特性
- **多格式支持**：
  - **JPEG**：采用传统标准，支持质量参数调节。
  - **HEIF (HEIC)**：支持高效图像格式，具备更高的压缩率和更好的色彩深度，专门优化了 99% 近无损模式。
  - **RAW (DNG)**：通过 `RawMediaStore` 保存原始信息，保留后期处理的最大可能性。
- **深度元数据（EXIF）管理**：
  - 全面记录：ISO、快门速度、光圈、焦距（含 35mm 等效）、曝光补偿、闪光灯状态、白平衡模式等。
  - **高精度计算**：自动计算 APEX 标准的快门速度值和光圈值。
  - **厂商扩展**：集成了制造商、型号及自定义软件标识。
- **存储架构**：
  - 完美适配 Android Q (API 29) 及以上版本的 `Scoped Storage`。
  - 使用 `IS_PENDING` 机制确保文件写入完整前不被系统相册索引。
  - 集成 `MediaScanner` 确保旧版本 Android 系统的兼容性。

## 3. 完整性评估
### 优势
- **EXIF 丰富度**：不仅记录基础信息，还包括了位置（GPS）、子秒级精度（SubSecTime）、感测方法等专业信息。
- **HEIF 优化**：解决了 Android 系统保存 HEIF 时 EXIF 丢失的通病，通过手动写入 EXIF Payload 实现了元数据与 HEIF 的完美结合。
- **流程健壮性**：支持内存管理（显式调用 `recycle`）和异常回滚（保存失败时删除 MediaStore 条目）。

### 待改进点
- **多帧合成**：目前的拍摄流程是单帧处理，尚未集成 HDR、夜景模式或超分辨率等需要多帧对齐与融合的算法。
- **并发优化**：对于高频率连拍，目前主要依赖后台 Handler，可以进一步优化为生产者-消费者队列模式以应对极高吞吐量。

## 4. 总结
拍摄流程模块在数据完整性和系统兼容性方面做得非常出色，其对元数据的重视程度达到了专业摄影工具的级别。
